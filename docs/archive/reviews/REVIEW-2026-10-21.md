## Intended scope

One native binary for local, authorized, read-only PHP discovery and a qualified patch plan, plus *optional* signed IOC-based incident triage. Ordinary users should run `php2shell scan`, read `reports/*.html`, and know what to verify or update next. It does not run PHP and does not send exploit traffic.

## Validated against PHP's 21 October 2026 official advisory

CVE-2026-109618 and CVE-2026-109619 are unauthenticated RCE; first upstream fixed versions are **8.2.35 / 8.3.36 / 8.4.27 / 8.5.12**. PHP explicitly includes mod_php, PHP-FPM, CGI, FrankenPHP and LiteSpeed. Some vendors provide backports with older-looking version strings. Only an update or a verified vendor-equivalent patch is adequate; configuration mitigations are partial. Sources:

## Findings and outstanding risks

| Priority | Finding | Risk / required action |
|---|---|---|
| HIGH / release gate | Actual HTTP-serving PHP SAPI and vendor-backport status are not automatically attested. | A patched CLI or package does not establish that Apache/FPM/IIS is serving a fixed build. Build evidence chains for active SAPI, package build, pools, containers and service restarts; never claim a host safe from the current inventory. |
| HIGH / release gate | No independently validated, PHP2Shell-specific compromise rules ship with the project. | Default scan is **not** a compromise assessment. An HTTP access-log literal cannot reliably detect arbitrary exploitation (request body, worker activity and memory corruption may be unlogged). Require tested sources, rule provenance and EDR/process/forensic coverage before advertising detection. |
| HIGH / usability | Windows/IIS exact PHP version and RPM/rpm-based systems are not supported by reliable passive version extraction. | Generic PHP locations and processes may be found, but a scan can return unknown on real production systems. Add vendor-aware package parsing and safe PE metadata for Windows without executing discovered binaries. Test on representative hosts. |
| MEDIUM / safety | Filesystem TOCTOU / symlink races remain possible in adversary-controlled roots. | `Lstat` followed by `Open` is not an atomic no-follow guarantee. Run without elevated privileges when possible; use platform-specific secure open and frozen forensic copies for high-risk IR. |
| MEDIUM / investigation | Explicit access logs are capped at 32 MiB; webroot hash inventory is capped and log/EDR discovery is manual. | A limited scan is not a negative finding. Include missing/truncated coverage. Evaluate optional bounded log discovery only with privacy and permission controls. |
| MEDIUM / supply chain | Release binaries are not OS code-signed and rule-publisher trust requires out-of-band Ed25519 key provisioning. | Validate checksums and build provenance, configure release protections, publish a verified public key/fingerprint using an independent authenticated channel. A signature authenticates a publisher, not rule correctness. |
| MEDIUM / privacy | Reports include hostnames, file paths and software metadata; Windows report protection depends on parent ACL. | Keep reports local, enforce least privilege and do not publish or email raw artifacts. No auto-upload is implemented. |
| MEDIUM / release governance | ~~No approved license~~ **Resolved (post-review):** Apache-2.0 in `LICENSE`. | Historical finding from 2026-10-21; no longer a blocker. |
| LOW / release workflow | GitHub Actions currently manages unsigned alpha assets. | Review each candidate; use protected releases and verify actual published downloads and runner tests. Passing CI is not equivalent to production validation. |

## Improvements included in v2.2.0-alpha.2

## Suggested release gates

1. Verify local test outputs and that the hosted GitHub commit matches the reviewed code; do not push during an unrelated alpha workflow.
2. On a *real* IIS host and representative Debian/Ubuntu, RPM and Docker PHP setups, confirm detection coverage, rights, bounded resource usage and zero disruption.
3. Build trusted SAPI/vendor patch-state verification and integrate tested compromise indicators / historical evidence coverage.
4. Approve source-code license, binary-signing strategy, key distribution and release permissions.
5. Publish signed/traceable release and verify actual Windows/Linux downloads on clean hosts.

**Assessment:** suitable as a clearly labeled development alpha for host inventory and *conditional* patch triage. **Not production validated** and cannot determine that a server has never been compromised.
