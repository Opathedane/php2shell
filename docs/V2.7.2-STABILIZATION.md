## Status JSON write failure (reproduced)

| Condition | Exit code | Reports | Status JSON | Stderr |
| --- | --- | --- | --- | --- |
| HTML+CSV written; primary status path unwritable but sibling alt writable (e.g. `--status-json` points at a directory named `*.status.json`) | **0** (coverage OK) | Present | Written to `*.failed-<execId>.status.json` | Quiet status line only (no `OUTPUT_WRITE_FAILED` — alt succeeded) |
| HTML+CSV written; primary **and** alt fail (status dir `chmod 555`) | **0** (coverage OK) | Present | **Neither** written | `ERROR: [OUTPUT_WRITE_FAILED]…` + quiet line `errors=OUTPUT_WRITE_FAILED`; remediation says collect HTML/CSV |
| Reports **not** written; status write fails with prior exit 0 | **1** | Absent | Failed | Fatal (code path in `finishScan`) |

**Intune / PSADT consequence:** Exit **0** with HTML+CSV present does **not** guarantee status JSON exists. Unattended packages that gate only on exit code still get reports; packages that require `.status.json` for fleet ingest must treat `OUTPUT_WRITE_FAILED` / missing status as a packaging defect and collect HTML/CSV anyway. Prefer unique `--out` names so overwrite does not force the alt path.
