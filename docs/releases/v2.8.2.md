# PHP2Shell v2.8.2

**Unreleased draft — do not tag or publish until approved.**

Latest public release remains **[v2.8.1](https://github.com/Opathedane/php2shell/releases/tag/v2.8.1)** (published 25 October 2026).

Focused **discovery correctness maintenance** for confirmed WampServer inventory gaps reported against v2.8.1. Preserves CVE vulnerability thresholds, investigation/telemetry behaviour, active-runtime attestation limits, exit codes, HTML/CSV/status JSON, fleet CSV **v3**, and report schemas. Offline and read-only by default. No active exploitation, network probing, broad filesystem scanning, PHP binary execution, or unrelated discovery expansion.

**Merge baseline:** WampServer maintenance landed on `main` via PR #47 (tip `75b077b` / merge `bf70ade`).

## What changed

### WampServer-style PHP version path inference

- Directory segments formatted as `phpX.Y.Z` (e.g. `C:\wamp64\bin\php\php7.4.33\php.exe`) are recognized in addition to bare `X.Y.Z`
- Inferred versions remain **`binary_path_inferred_version`** with provenance **`path_inferred`** and confidence **`MEDIUM`**
- Path-inferred versions are **not** verified binary metadata and are **not** proof of the active HTTP-serving runtime
- Marker-free binaries under these layouts can receive legacy/EOL patch review messaging when a comparable version is inferred — still requiring manual verification

### Bounded WampServer configuration discovery

- Apache config roots expanded with bounded globs: `C:\wamp64\bin\apache\*\conf`, `C:\wamp\bin\apache\*\conf` (`filepath.Glob` only; not recursive host-wide scanning)
- Well-known php.ini patterns include `C:\wamp64\bin\php\*\php.ini` (alongside existing `C:\wamp\...`)
- Reuses existing Apache / php.ini parsers and coverage semantics
- Static configuration alone still does **not** verify an active web-serving PHP runtime

### Clearer verified / inferred / unknown reporting

- Executive HTML, CLI summary, and `binary_paths` coverage distinguish:
  - verified binary metadata versions
  - path-inferred versions (MEDIUM; manual verification required)
  - candidates without comparable versions
- Path-inferred findings are not presented as confirmed installations or proven vulnerability exposure

### Deduplication across discovery sources

- Apache handler binary follow-up skips re-inventory when the same PHP binary path is already recorded (e.g. well-known / PATH discovery)
- Handler/module configuration evidence is still recorded
- Install grouping and patch assessment stay one logical install tree / one row per distinct binary path

## Honesty (required reading)

| Observation | Means |
| --- | --- |
| Verified binary metadata | Passive extracted from embedded/PE markers — still **not** proof the binary serves HTTP |
| Path-inferred (`phpX.Y.Z` / bare `X.Y.Z`) | Directory-derived inventory lead — **MEDIUM** confidence; requires manual verification |
| Apache / php.ini candidates | Configured paths only — **not** active runtime or effective settings attestation |
| Active web runtime | Remains unverified unless separately established; inventory never upgrades to “Verified” from path/config alone |

## Limitations (read before deploying)

- Process completion / exit **0** is **not** a vulnerability or compromise clearance
- Path-inferred versions are inventory leads, not confirmed installs or proven exposure
- Missing evidence is **not** a negative finding; absence of PHP findings is **not** proof a host is PHP-free
- Active HTTP-serving SAPI is still **not** attested from path inference or Apache/php.ini inventory
- Custom drive letters / nonstandard Wamp layouts still need `--config-root` / `--deep-root` / `--php-ini`
- Vendor backports require separate verification
- Binaries remain **unsigned**; verify `SHA256SUMS`
