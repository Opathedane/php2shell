# PHP2Shell v2.8.1

**Unreleased draft — do not tag or publish until approved.**

Latest public release remains **[v2.8.0](https://github.com/Opathedane/php2shell/releases/tag/v2.8.0)**.

Focused **security detection** maintenance update driven by October 25, 2026 industry reporting on real-world PHP2Shell exploitation research (ReliaQuest Threat Spotlight, Unit 42 CVE analysis, The Hacker News coverage). Preserves v2.8.0 discovery surface, exit codes, HTML/CSV/status JSON, fleet CSV, and CVE vulnerability thresholds. Offline and read-only by default. No active exploitation, network probing, new telemetry sources, new PHP discovery, or DFIR platform expansion.

## What changed (detection only)

### Error-log research patterns (ReliaQuest-aligned)

- Detect PHP `zend_mm_heap corrupted` (`php_zend_mm_heap_corrupted`)
- Detect Apache `AH00052` **Abort** / SIGABRT (`apache_child_abort`) in addition to existing Segmentation fault
- Existing Datadog patterns retained: OOM **Unknown on line 0**, AH00052 Segmentation fault

### Stronger multi-signal correlation (evidence ladder)

- `correlated_error_sequence` when **OOM Unknown on line 0** appears with heap corruption and/or worker crash/abort within ≤2 minutes **on the same error-log file**
- Confidence **suspected** only when ≥3 distinct research kinds are present **or** the same Apache `child pid` appears on ≥2 crash/abort lines in the cluster
- Two-kind temporal pairs without shared WorkerPID stay **unconfirmed**
- Cross-file / cross-host error joins are refused; duplicate identical kind sets emit once
- Temporal proximity is **never** presented as proof of one shared HTTP request or process
- Does **not** claim confirmed exploitation or host compromise

### Access-log POST 5xx (correlation-only)

- Collect `access_post_server_error` for POST responses with 5xx status
- **Never** a standalone attempt lead (avoids flooding from ordinary application errors)
- When temporally near a research error pattern (±15m), emits `correlated_attempt_signals` at confidence **unconfirmed** (time-only; ordinary apps also return 5xx; no shared PID with access lines)
- Repeated POST 5xx events collapse to the nearest event per error line (no artificial strengthening)

### Process telemetry (Unit 42 agentic markers)

- Classify exact published delimiters `==SHELLUSER==` / `==PASSWD==` as `agentic_section_delimiter` when a web/PHP parent is present
- Raw command lines, credentials, and token values are **never** retained in findings or reports
- Bare `passwd` paths do not match

## Explicitly not claimed / not added

- Does **not** detect every technique in the October 25 articles (LDAP/AD enumeration tooling lists, request-body `p2s-rider` markers, multipart upload-progress values, or same-PID access↔error identity when PID is absent)
- Existing WAF query-string **presence** of `PHP_SESSION_UPLOAD_PROGRESS` unchanged; body/multipart values remain unavailable in supported schemas
- No vulnerability threshold changes; no new PHP discovery; no live EDR/WAF APIs
