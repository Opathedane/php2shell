# PHP2Shell v2.8.1

**Unreleased draft — do not tag or publish until approved.**

Latest public release remains **[v2.8.0](https://github.com/Opathedane/php2shell/releases/tag/v2.8.0)** (published 25 October 2026).

Focused **security-detection maintenance** update informed by public PHP2Shell exploitation research from **ReliaQuest** and **Palo Alto Networks Unit 42** (research published / widely covered **22–25 October 2026**). The **v2.8.1 product release date is independent** of those research publication dates and will be recorded only when this release is tagged and published.

Preserves the v2.8.0 discovery surface, exit codes, HTML/CSV/status JSON, fleet CSV **v3**, and CVE vulnerability thresholds. Offline and read-only by default. No active exploitation, network probing, new telemetry sources, new PHP discovery, or DFIR platform expansion.

**Merge baseline:** detection work landed on `main` via PR #44 (`7205591`).

## What changed (detection only)

### New memory-corruption and Apache worker-crash indicators

- PHP `zend_mm_heap corrupted` → `php_zend_mm_heap_corrupted` (ReliaQuest-aligned)
- Apache `AH00052` **Abort** / SIGABRT → `apache_child_abort` (in addition to existing Segmentation fault)
- Existing Datadog-backed patterns retained: OOM **Unknown on line 0**, AH00052 Segmentation fault
- Individual heap / OOM / Abort matches are **`suspected` research patterns only** — detail text states they are **not** proof of exploitation or host compromise; they never set `CONFIRMED_COMPROMISE`

### Improved multi-signal correlation

- `correlated_error_sequence` when **OOM Unknown on line 0** appears with heap corruption and/or worker crash/abort within ≤2 minutes **on the same error-log file**
- Cross-file / cross-host error joins are refused
- Duplicate identical kind sets emit **once** (repeated log lines do not multiply sequence findings)
- Apache `child pid` is extracted when present and disclosed; same-PID language is **distinct from same-request proof**

### More conservative confidence handling

| Evidence | Confidence |
| --- | --- |
| ≥3 distinct research kinds (same file, ≤2m) | `suspected` |
| Same Apache WorkerPID on **≥2 distinct** crash/abort pattern kinds | `suspected` (still not same-request proof; duplicate same-kind Abort lines do **not** count) |
| Two-kind time-only sequence (no shared distinct-kind PID) | `unconfirmed` |
| POST 5xx ↔ research error (±15m) | `unconfirmed` (correlation-only; ordinary apps emit 5xx) |
| Long POST request-target ↔ error | `unconfirmed` (unchanged) |

POST 5xx events are **never** standalone attempt leads. Missing or unreliable timestamps cannot create correlations. Missing PID is disclosed and keeps weaker pairings at `unconfirmed`.

### Additional process telemetry markers

- Exact Unit 42 delimiters `==SHELLUSER==` / `==PASSWD==` → `agentic_section_delimiter` **only** when a web/PHP parent is present
- Raw command lines, credentials, and tokens are **never** retained
- Lowercase / partial / bare `passwd` strings and non-web parents do not match

## CLI / HTML honesty

- HTML investigation table shows per-finding **Confidence** (`suspected` / `unconfirmed`) separately from host statuses
- Independent statuses remain: `ExploitationAttemptStatus`, `PossibleCompromiseStatus`, `InvestigationCoverage`, legacy signed-IOC `CompromiseStatus`
- Missing investigation inputs stay **`NOT_ASSESSED`** (not a negative clearance); never `CONFIRMED_COMPROMISE` or `CLEAN`

## Explicitly not claimed / not added

- Does **not** detect every technique in October 2026 articles (LDAP/AD tooling inventories, request-body `p2s-rider` markers, multipart upload-progress values, or access↔error same-request identity when PID is absent)
- Existing WAF query-string **presence** of `PHP_SESSION_UPLOAD_PROGRESS` unchanged; body/multipart values remain unavailable in supported schemas
- No vulnerability threshold changes; no new PHP discovery; no live EDR/WAF APIs; no new detection families beyond the ReliaQuest/Unit 42–aligned IR assists above
